# 뭐먹지?

단체(회사, 동아리, 친구 모임)에서 메뉴를 고를 때, 익명으로 메뉴를 제안하고 +1/-1로 투표해서 정하는 웹 서비스입니다.

> MVP(기능 1~5)를 모두 만들었습니다. 다음은 배포와 기능 6(AI 합치기)입니다.

## 주요 기능

1~5가 MVP이고, 6은 MVP를 다 만든 뒤에 붙입니다.

1. ✅ **방 만들기 + 링크로 참여**: 회원가입이나 닉네임 없이 링크로 바로 익명 참여
   - 방장이 단계별 시간을 정해서 방을 만들고, 참여 링크를 공유
     - 30초, 1분, 2분, 3분, 5분, 10분, 30분, "제한 없음" 중에 고르거나, "직접 설정"으로 1~60분을 씀. 제한 없는 단계는 모두 끝내거나 방장이 넘길 때 넘어감
     - 기본은 제안·합치기·투표 5분, 랜덤 선택 1분
   - "참여 인원 5명 · 지금 접속 중 3명"처럼 들어온 사람 수와 지금 화면을 열어 둔 사람 수가 실시간으로 보임 (누가 들어왔는지, 누가 접속 중인지는 안 보임)
   - 새로고침해도 같은 참여자로 유지, 방 정원은 50명
2. ✅ **익명 메뉴 제안**: 한 사람이 메뉴 하나씩 제안, 원하지 않으면 "다 좋음"
   - 방장이 "시작"을 누르면 제안 단계가 시작되고, 남은 시간이 모든 화면에서 똑같이 줄어듦
   - 제안된 메뉴가 실시간으로 보이고(누가 냈는지는 안 보임), 단계가 끝나기 전까지 바꾸거나 취소 가능
   - 시간이 다 되거나, 모두 끝내거나, 방장이 "다음 단계로"를 누르면 넘어감 (동시에 일어나도 한 번만)
3. ✅ **비슷한 메뉴 합치기**: 같은 메뉴에 표가 갈라지지 않게, 제안자들이 동의하면 하나로 합침
   - ✅ 띄어쓰기·대소문자만 다른 같은 이름 메뉴("제육 볶음"과 "제육볶음")를 자동으로 묶고, 묶인 제안자들에게만 "합칠까요?"를 익명으로 물음
   - ✅ 동의한 메뉴 중 하나를 서버가 무작위로 대표로 뽑고, 나머지는 대표에 합쳐짐 (누가 어떻게 답했는지는 안 보임)
   - ✅ "합치기 끝냄", 합치기 시간, 모두 끝내면 바로 투표 단계로 (동시에 답해도 결과는 한 번만)
   - ✅ 직접 합치기: 자동으로 안 묶인 같은 메뉴에 "이 메뉴에 합치기"를 요청하고, 받아들여지면 요청받은 메뉴가 대표로 남음 (한 메뉴는 한 번에 요청 하나, 동시에 요청해도 하나만 성공)
4. ✅ **투표 + 결과**: 한 사람당 최대 2표, 각 표는 +1(먹고 싶다) 또는 -1(먹기 싫다), 총점 1등으로 결정
   - 한 메뉴에 1표, 제출하거나 "다 좋음"을 누르면 바꿀 수 없음 (같은 사람이 동시에 여러 번 내도 하나만 저장)
   - 투표 중에는 점수를 숨기고(누가 어디에 찍었는지 짐작할 수 없게), 끝나면 메뉴별 +1/-1/총점 공개
   - 모두 내면 시간이 남아 있어도 바로 결과, 메뉴가 하나뿐이면 투표 없이 결정
5. ✅ **재투표 + 랜덤 선택**: 결과가 안 나는 경우에도 반드시 메뉴 하나로 끝남
   - 1등이 동점이면 동점 메뉴만 놓고 한 번 더 투표(첫 투표 점수는 공개, 재투표 점수는 끝난 뒤 공개)
   - 재투표도 동점이면 재투표 1등끼리 중에서, 아무도 안 찍으면 동점 메뉴 중에서 서버가 무작위로 결정
   - 아무도 메뉴를 내지 않았거나 아무도 투표하지 않으면, 서버가 참여자 한 명을 무작위로 뽑고 그 사람이 메뉴를 정함 (누가 뽑혔는지는 본인만 앎). 나온 메뉴를 고르면 입력칸에 들어가고, "이 메뉴로 정하기"를 눌러야 정해짐
   - 시간 안에 안 정하면 다른 사람을 다시 뽑음 (한 바퀴 안에서는 같은 사람을 다시 안 뽑음). 방장은 "다른 사람 뽑기"로 바로 넘길 수 있음. 랜덤 선택이 "제한 없음"이면 자동으로 다시 뽑지 않고 방장이 넘길 때만 다시 뽑음
   - 모두 한 번씩 뽑혀도 안 정해지면 자동으로는 더 뽑지 않음 (모두 나가 버린 방이 끝없이 다시 뽑지 않게)
   - 결과 화면에 어떻게 결정됐는지(투표, 재투표, 무작위, 뽑힌 사람)와 메뉴별 점수를 보여줌
6. **AI 합치기**: 이름이 달라도 같은 메뉴("제육", "할매집 제육")를 AI가 묶음

진행 단계와 화면은 SSE로 모든 참여자에게 실시간으로 갱신됩니다. 되돌릴 수 없는 버튼도 확인창 없이 바로 처리하고, 바꿀 수 없다는 것은 화면에 미리 적어 둡니다.

|---|---|

| DB | MySQL 9.7, Flyway (테이블 변경 이력 관리) |

## 로컬에서 실행하기

### 준비물

- JDK 25
- Node.js 26 이상
- Docker Desktop

### 1. 환경 변수 파일 만들기

`.env.example`을 복사해 같은 폴더에 `.env`를 만들고 비밀번호 두 개(`DB_PASSWORD`, `DB_ROOT_PASSWORD`)를 채웁니다. `.env`는 깃에 올라가지 않습니다.

### 2. MySQL 실행

```bash
docker compose up -d --wait
```

### 3. 백엔드 실행

```bash
cd backend
./gradlew bootRun
```

브라우저에서 http://localhost:8080/actuator/health 를 열어 `{"status":"UP"}`가 나오면 서버와 DB 연결이 정상입니다.

### 4. 프론트 실행

```bash
cd frontend
npm install
npm run dev
```

http://localhost:5173 에서 화면을 볼 수 있습니다. 개발 중에는 `/api` 요청이 자동으로 백엔드(8080)로 전달됩니다.

**써보기**: 방을 만든 뒤 "참여 링크 복사"로 링크를 복사해서 시크릿 창이나 다른 브라우저에 붙여넣으면, 처음 창의 참여 인원이 새로고침 없이 늘어납니다. 시크릿 창은 쿠키를 따로 쓰기 때문에 다른 참여자로 들어갑니다. 처음 창(방장)에서 "시작"을 누르면 두 창 모두 제안 화면으로 바뀌고, 한쪽에서 메뉴를 내면 다른 쪽 목록에 바로 나타납니다. 두 창에서 "제육 볶음"과 "제육볶음"처럼 띄어쓰기만 다르게 내면, 합치기 단계에서 두 창 모두 "이 메뉴들과 합칠까요?" 질문을 받습니다. 둘 다 "합치기"를 누르면 둘 중 하나만 남고, 다른 쪽 창에는 "내 메뉴가 ○○(으)로 합쳐졌어요"가 보입니다. "할매집 제육"과 "제육볶음"처럼 이름이 다른 메뉴는 한쪽 창의 "이 메뉴에 합치기"로 요청하고, 다른 쪽 창에서 "합치기"를 누르면 요청받은 메뉴가 남습니다. 두 창 모두 "합치기 끝냄"을 누르면 투표가 시작되고, 둘 다 표를 내면 바로 결정된 메뉴와 메뉴별 점수가 나옵니다. 두 창이 서로 다른 메뉴에 +1을 주면 동점이라 재투표가 되고, 투표에서 둘 다 "다 좋음"을 누르면 랜덤 선택이 됩니다. 랜덤 선택에서는 뽑힌 창에만 메뉴를 정하는 칸이 나옵니다.

### 여러 명으로 테스트하기

개발 서버가 켜져 있을 때 http://localhost:5173/dev-board.html 을 열면 **여러 명 테스트 화면**이 나옵니다. 창을 여러 개 띄우지 않아도, 한 탭에 칸이 최대 4개 나란히 보이고 칸마다 다른 참여자가 됩니다.

- 위쪽 "빠른 방 만들기"의 [시간 제한 없음] 또는 [모두 30초]를 누르면 칸 1이 방장인 방이 바로 만들어집니다. 시간을 직접 고르려면 "방 만들기 화면으로"를 누르고 칸 1에서 만듭니다.
- "모든 칸 들어가기"를 누르면 나머지 칸도 같은 방에 들어옵니다. 칸마다 "들어가기", "닫기", "새로고침"으로 늦게 들어오기, 나가기, 새로고침을 해 볼 수 있습니다.
- 칸 N은 앱을 `/p/N/...` 주소로 띄우고, 개발 서버(Vite)가 쿠키 경로 앞에 `/p/N`을 붙여서 칸마다 쿠키를 따로 저장하게 합니다. 백엔드는 그대로입니다.
- 개발할 때만 쓰는 화면이라 배포용 빌드에는 들어가지 않습니다. CI가 이를 검사합니다.

### 테스트

```bash
cd backend
./gradlew test
```

Docker Desktop이 켜져 있어야 합니다. 테스트가 테스트 전용 MySQL을 자동으로 띄우고 끝나면 지웁니다.

배포 전에는 [docs/manual-test.md](docs/manual-test.md)의 체크리스트를 따라 여러 명 테스트 화면에서 화면을 직접 확인합니다.

## API

| 요청 | 하는 일 |
|---|---|
| `POST /api/rooms` | 방 만들기. 본문에 단계별 시간(초, 30~3600에 30초 단위, 0은 제한 없음)을 넣고, 안 넣은 단계는 기본값(제안·합치기·투표 300초, 랜덤 선택 60초). 만든 사람이 방장이 되고 참여자 쿠키를 받음 |
| `POST /api/rooms/{code}/participants` | 링크로 참여. 이미 그 방 쿠키가 있으면 같은 참여자(200), 새로 들어오면 새 쿠키(201) |
| `GET /api/rooms/{code}` | 방 상태(단계, 시간, 참여 인원 수, 지금 접속 중인 사람 수, 메뉴, 합치기 그룹, 투표 후보, 점수, 결과와 결정 이유)와 내 정보(방장인지, 내 메뉴, 답할 질문, 내 투표지, 내가 뽑혔는지 등) |
| `GET /api/rooms/{code}/events` | SSE. 연결하자마자 지금 화면 정보(방 상태 + 내 정보), 이후 바뀔 때마다 새 정보. 내 정보는 본인 것만 옴. 이 연결 수로 "지금 접속 중"을 세고, 10초마다 보내는 신호로 끊긴 연결을 정리함(닫은 뒤 10~20초 안에 줄어듦) |
| `POST /api/rooms/{code}/next-phase` | 방장 전용 "시작"/"다음 단계로". 본문에 화면에 보이던 단계(`from`)를 넣어 두 번 눌러도 한 단계만 넘어감. 랜덤 선택에서는 "다른 사람 뽑기"이고, 화면에 보이던 뽑기 차례 번호(`pickTurn`)도 함께 보냄 |
| `PUT /api/rooms/{code}/me/proposal` | 내 메뉴 제안. 이미 냈으면 이름만 바뀜 |
| `POST /api/rooms/{code}/me/all-good` | "다 좋음". 이미 낸 메뉴는 취소됨 |
| `PUT /api/rooms/{code}/me/merge-answers/{groupId}` | 합치기 질문(자동 그룹, 받은 직접 요청)에 답하기(`{"agree": true}`). 한 번 답하면 바꿀 수 없고, 같은 답을 다시 보내면 그대로 성공 |
| `POST /api/rooms/{code}/me/merge-requests` | 직접 합치기 요청(`{"targetMenuId": "..."}`). 받아들여지면 요청받은 메뉴가 대표로 남음. 취소할 수 없음 |
| `POST /api/rooms/{code}/me/merge-done` | "합치기 끝냄". 답하지 않은 질문은 "합치지 않기"로 처리됨. 보낸 요청의 답을 기다리는 동안에는 누를 수 없음 |
| `PUT /api/rooms/{code}/me/ballot` | 투표지 내기. 표 1~2개(`{"votes": [{"menuId": "...", "point": 1}]}`) 또는 "다 좋음"(`{"allGood": true}`). 한 번 내면 바꿀 수 없고, 같은 내용을 다시 보내면 그대로 성공. 재투표 중이면 재투표 투표지로 냄(동점이었던 메뉴에만) |
| `POST /api/rooms/{code}/me/pick` | 랜덤 선택에서 뽑힌 사람이 메뉴 정하기(`{"menuName": "..."}`, 1~30자). 메뉴 목록에 없는 이름도 됨. 정하면 바로 결정 |

에러는 `{"status": 409, "detail": "방 정원이 가득 찼습니다.", "code": "ROOM_FULL"}`처럼 Spring 표준 형식(ProblemDetail)에 `code`를 붙여 보냅니다.
