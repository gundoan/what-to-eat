# 배포 전 직접 테스트 체크리스트

자동 테스트는 규칙(한 메뉴에 2표 막기, 동점이면 재투표 등)을 코드로 확인한다. 이 체크리스트는 사람이 화면을 직접 쓰면서 **화면이 제대로 보이는지, 흐름이 자연스러운지**를 확인한다.

- 배포 전에 시나리오 1~12를 한 번 다 한다. 1~2시간쯤 걸린다.
- 배포한 뒤에는 실제 휴대폰으로 맨 아래 "배포한 뒤 확인"만 한다.
- `- [ ]`는 "이렇게 보여야 한다"는 뜻이다. 다르게 보이면 맨 아래 "찾은 문제"에 적는다(채팅으로 알려 주면 Claude가 적는다).
- 하는 동안 `- [x]`로 바꿔 표시해도 되지만 커밋하지 않는다. 다 하면 "테스트 기록"에 한 줄 남긴다. 다음에도 빈 체크리스트로 다시 쓰기 위해서다.
- 문제를 고칠 때는 그 문제를 그대로 일으키는 테스트를 먼저 쓰고, 그 테스트가 통과하게 고친다.

## 준비

1. MySQL, 백엔드, 프론트 개발 서버를 켠다. 켜는 법은 [README의 "로컬에서 실행하기"](../README.md#로컬에서-실행하기)에 있다.
2. 크롬에서 http://localhost:5173/dev-board.html 을 연다. 이 화면이 **여러 명 테스트 화면**이다. 한 탭 안의 칸마다 다른 참여자가 된다.
3. 시나리오마다 칸 수를 시나리오에 적힌 대로 바꾸고, 위쪽 **빠른 방 만들기**의 [시간 제한 없음]을 누른다. 칸 1이 방장인 방이 바로 만들어진다. 시간이 다 되는 것을 보는 시나리오(6, 8, 10)만 [모두 30초]를 누른다.
4. 시간 제한이 없어도 모두 끝내면 바로 다음 단계로 넘어간다. 그러니 칸을 하나씩 천천히 눌러도 된다.

### 여러 명 테스트 화면 쓰는 법

| 버튼 | 하는 일 |
|---|---|
| 칸 수 | 1~4. 칸 하나가 참여자 한 명이다 |
| 빠른 방 만들기 | [시간 제한 없음] 또는 [모두 30초]로 방을 바로 만든다. 칸 1이 방장으로 들어가고 나머지 칸은 닫힌다 |
| 방 주소, 주소 복사 | 만든 방의 전체 주소. 복사해서 엣지나 크롬 시크릿 창에 붙여 넣으면 칸 밖의 참여자로 들어간다 |
| 방 만들기 화면으로 | 칸 1은 방 만들기 화면으로 가고 나머지 칸은 닫힌다. 시간을 직접 고를 때 쓴다 |
| 모든 칸 들어가기 | 만든 방에 닫혀 있는 칸을 모두 들여보낸다 |
| (칸의) 들어가기 | 그 사람만 방에 들어온다(늦게 들어오기). 전에 들어갔던 칸이면 같은 참여자로 돌아온다 |
| (칸의) 닫기 | 그 사람이 창을 닫고 나간다. 참여 인원은 그대로이고, "지금 접속 중"만 10~20초 뒤에 줄어든다 |
| (칸의) 새로고침 | 그 사람이 새로고침한다 |

새 방에서는 쿠키도 새로 받아서 모두 새 참여자가 된다.

### 알아 둘 점

- 빠른 방 만들기로 만들거나 칸 1에서 방을 만들면, 칸 1이 방장이다.
- 확인창은 없다. 제출, "다 좋음", 합치기 요청, 다른 사람 뽑기, 메뉴 정하기는 누르면 바로 처리되고 되돌릴 수 없다.
- 테스트 화면을 쓰는 동안 **같은 크롬에서 이 앱을 다른 탭으로 열지 않는다**. 브라우저는 한 주소에 연결을 6개까지만 여는데, 칸마다 하나씩 계속 쓰고 있어서 탭을 더 열면 화면이 멈출 수 있다. 칸 밖의 창이 필요하면 엣지나 크롬 시크릿 창을 쓴다.

## 시나리오

### 1. 기본 흐름: 4명이 투표로 결정 (칸 4개)

이 시나리오만 빠른 방 만들기 대신 방 만들기 화면을 쓴다. 기본 시간, "제한 없음", "직접 설정"을 확인하기 위해서다.

1. "방 만들기 화면으로"를 누르고 칸 1의 방 만들기 화면을 본다.
   - [ ] 처음 골라져 있는 시간이 제안 5분, 합치기 5분, 투표 5분, 랜덤 선택 1분이다.
   - [ ] 시간 목록이 30초, 1분, 2분, 3분, 5분, 10분, 30분, 제한 없음, 직접 설정이다.
2. 투표를 "직접 설정"으로 바꾼다.
   - [ ] 옆에 "[ ]분" 칸이 나오고, 고르던 5분이 "5"로 미리 들어가 있다.
   - [ ] 61이나 0을 쓰면 "1~60 사이의 숫자(분)로 써 주세요."가 나오고 "방 만들기"가 눌리지 않는다.
   - [ ] 칸을 비우면 안내는 없고 "방 만들기"만 눌리지 않는다.
   - 15를 쓴다.
3. 제안을 "제한 없음"으로 바꾸고 "방 만들기"를 누른다.
   - [ ] 위쪽에 방 코드가 나온다.
   - [ ] 칸 1에 "내가 방장이에요. 다른 사람에게는 보이지 않아요."와 "시작" 버튼이 있다.
4. "모든 칸 들어가기"를 누른다.
   - [ ] 모든 칸에 "참여 인원 4명 · 지금 접속 중 4명"이 보인다.
   - [ ] 칸 2~4에는 방장 표시와 "시작" 버튼이 없고, "방장이 시작하면 메뉴 제안이 시작돼요."가 보인다.
   - [ ] 모든 칸의 단계별 시간이 "제안: 제한 없음, 합치기: 5분, 투표: 15분, 랜덤 선택: 1분"이다.
5. 칸 1에서 "시작"을 누른다.
   - [ ] 모든 칸이 "메뉴 제안 중"으로 바뀌고, 남은 시간 대신 "시간 제한 없음"이 보인다.
   - [ ] "다음 단계로" 버튼은 칸 1에만 있다.
   - [ ] 메뉴 입력칸에 "음식 이름 (예: 포테이토 피자)"가 흐리게 보인다.
6. 칸 1 "라면", 칸 2 "김치찌개", 칸 3 "돈까스"를 차례로 제안한다.
   - [ ] 제안할 때마다 모든 칸의 "제안된 메뉴"에 바로 나타난다.
   - [ ] 목록은 올린 순서가 아니라 가나다순이다(김치찌개, 돈까스, 라면).
   - [ ] 자기가 낸 메뉴에만 "(내 메뉴)"가 붙는다.
   - [ ] "4명 중 3명 끝냄"처럼 숫자만 보이고, 누가 냈는지는 안 보인다.
7. 칸 3에서 "치즈돈까스"로 바꾼다("바꾸기").
   - [ ] 모든 칸에서 돈까스가 치즈돈까스로 바뀐다. "4명 중 3명 끝냄"은 그대로다.
8. 칸 4에서 "다 좋음"을 누른다.
   - [ ] 모두 끝내서, 시간이 남았어도 바로 "합치기 중"으로 바뀐다.
9. 합치기 단계(이름이 같은 메뉴가 없다).
   - [ ] 합치기는 기본 5분이라, 남은 시간이 5:00부터 줄어든다.
   - [ ] "합치기 현황"에 "아직 합치기가 없어요."가 보인다.
   - [ ] 칸 4는 "메뉴를 내지 않아서 합칠 게 없어요. 투표를 기다려 주세요."이고, 처음부터 끝낸 사람으로 센다("4명 중 1명 끝냄").
   - 칸 1~3에서 "합치기 끝냄"을 누른다.
   - [ ] 세 번째로 누르는 순간 바로 "투표 중"으로 바뀐다.
10. 투표한다. 칸 1: 김치찌개 +1, 라면 +1 / 칸 2: 김치찌개 +1, 치즈돈까스 -1 / 칸 3: 라면 -1 / 칸 4: 김치찌개 +1. 각자 "제출"을 누른다.
    - [ ] 고를 때마다 "남은 표"가 줄고, 2개를 고르면 다른 메뉴의 버튼은 눌리지 않는다.
    - [ ] 같은 버튼을 다시 누르면 취소되고, +1을 고른 메뉴에서 -1을 누르면 -1로 바뀐다.
    - [ ] 아무것도 고르지 않으면 "제출"이 눌리지 않는다.
    - [ ] 버튼 위에 "제출하거나 '다 좋음'을 누르면 바꿀 수 없어요."가 있고, "제출"을 누르면 확인창 없이 바로 낸다. 낸 뒤에는 "내가 낸 표: …"만 보이고 바꿀 수 없다.
    - [ ] 투표는 직접 설정한 15분이라, 남은 시간이 15:00부터 줄어든다.
    - [ ] 투표 중에는 점수가 안 보이고 "4명 중 N명 끝냄"만 바뀐다.
11. 마지막 사람이 제출하면 결과가 나온다.
    - [ ] 모든 칸에 "결정: 김치찌개"와 "투표로 결정됐어요."가 보인다.
    - [ ] 점수표가 김치찌개(+1 3, -1 0, 총점 3), 라면(1, 1, 0), 치즈돈까스(0, 1, -1) 순서다.
    - [ ] 칸마다 자기가 낸 표만 보인다(칸 3은 "내가 낸 표: 라면 -1").
    - [ ] "참여 링크 복사" 버튼이 사라진다.

### 2. 혼자서: 메뉴가 하나뿐 (칸 1개)

1. 칸 수를 1로 하고, 방을 만들어 "시작"을 누른다.
   - [ ] 참여 인원이 1명이어도 시작된다.
2. "제육볶음"을 제안한다.
   - [ ] 바로 "결정: 제육볶음"과 "메뉴가 하나라 투표 없이 결정됐어요."가 보인다. 합치기와 투표를 거치지 않고, 점수표도 없다.

### 3. 합치기: 자동 그룹과 직접 합치기 (칸 4개)

1. 모두 들어가서 시작한 뒤, 칸 1 "제육볶음", 칸 2 "제육 볶음", 칸 3 "제육볶음", 칸 4 "할매집 제육"을 제안한다.
   - [ ] 합치기 단계가 되면 "합치기 현황"에 칸 1~3의 메뉴가 한 그룹으로 "(이름이 같음) — 답한 사람 0/3"이 된다. 띄어쓰기만 다른 "제육 볶음"도 같이 묶인다.
   - [ ] 칸 1~3에만 "이 메뉴들과 합칠까요?"가 뜨고, 자기 메뉴에 "(내 메뉴)"가 붙는다. 칸 4에는 질문이 없다.
   - [ ] 칸 4에는 "지금은 합치기를 요청할 수 있는 메뉴가 없어요."가 보인다. 결과가 안 나온 그룹의 메뉴에는 요청할 수 없어서다.
2. 칸 1에서 "합치기"를 누른다.
   - [ ] 모든 칸에서 "답한 사람 1/3"으로 바뀐다. 누가 답했는지는 안 보인다.
   - [ ] 칸 1의 질문이 사라진다(답은 바꿀 수 없다).
3. 칸 2 "합치기", 칸 3 "합치지 않기"를 누른다.
   - [ ] 그룹이 "'…'(으)로 합쳐졌어요"로 바뀐다. 대표는 칸 1이나 칸 2의 메뉴 중에서 무작위다.
   - [ ] 대표가 아닌 쪽 칸에 "내 메뉴(…)가 '…'(으)로 합쳐졌어요. 투표만 하면 돼요."가 보인다.
   - [ ] 거절한 칸 3의 메뉴는 "남은 메뉴"에 따로 남는다. 대표가 칸 1의 "제육볶음"이면 같은 이름이 두 개 보이는데, 서로 다른 메뉴다.
4. 칸 4에서 대표 메뉴 옆 "이 메뉴에 합치기"를 누른다.
   - [ ] 누르기 전, "남은 메뉴" 위 안내에 "받아들여지면 그 메뉴가 대표로 남아요. 보낸 요청은 취소할 수 없어요."가 있다.
   - [ ] 누르면 확인창 없이 바로 보내지고, 모든 칸의 합치기 현황에 "할매집 제육 → … (직접 요청) — 답 기다리는 중"이 보인다.
   - [ ] 칸 4의 "합치기 끝냄"은 눌리지 않는다(답을 기다리는 동안).
   - [ ] 대표 메뉴를 낸 칸에 "합치기 요청을 받았어요"가 뜬다.
5. 대표 칸에서 "합치기"를 누른다.
   - [ ] 칸 4에 "내 메뉴(할매집 제육)가 '…'(으)로 합쳐졌어요."가 보인다. 대표 메뉴 이름은 그대로다(요청받은 쪽이 대표).
6. 칸 3에서 대표 메뉴에 "이 메뉴에 합치기"를 보내고, 대표 칸에서 "합치지 않기"를 누른다.
   - [ ] 현황에 "합치지 않았어요"가 보인다.
   - [ ] 칸 3에서 대표 메뉴 옆 "이 메뉴에 합치기"가 다시 생기지 않는다. 대표 칸에서도 칸 3 메뉴 옆에 버튼이 없다(거절된 두 메뉴는 어느 쪽으로도 다시 요청할 수 없다).
7. 대표 칸과 칸 3에서 "합치기 끝냄"을 누른다.
   - [ ] 바로 "투표 중"으로 바뀌고, 투표할 메뉴는 대표 메뉴와 칸 3의 "제육볶음" 두 개다.

### 4. 동점 → 재투표 → 결정 (칸 3개)

1. 칸 1 "김밥", 칸 2 "라면"을 제안하고 칸 3은 "다 좋음". 합치기에서 칸 1, 2가 "합치기 끝냄".
2. 투표: 칸 1 김밥 +1, 칸 2 라면 +1을 제출하고, 칸 3은 "다 좋음".
   - [ ] 마지막 사람이 내는 순간 "재투표 중"이 되고, "김밥, 라면 메뉴가 동점이라, 이 메뉴들만 놓고 한 번 더 투표해요."가 보인다.
   - [ ] 첫 투표 점수표는 보이지 않는다. 표를 내고 기다리는 동안에도 마찬가지다(점수표는 끝난 뒤 결과 화면에 나온다).
   - [ ] 투표할 메뉴는 김밥과 라면뿐이고, 첫 투표에서 "다 좋음"을 누른 칸 3도 다시 투표할 수 있다.
3. 재투표: 칸 1 김밥 +1, 칸 2 라면 +1, 칸 3 김밥 +1.
   - [ ] "결정: 김밥"과 "첫 투표가 동점이라, 재투표로 결정됐어요."가 보인다.
   - [ ] "첫 투표 결과"와 "재투표 결과" 표가 모두 보인다.
   - [ ] 칸 3에 "재투표에서 내가 낸 표: 김밥 +1"이 보인다.

### 5. 재투표도 결정이 안 될 때 (칸 2개)

1. 칸 1 "김밥", 칸 2 "라면" → 둘 다 "합치기 끝냄" → 칸 1 김밥 +1, 칸 2 라면 +1 → 재투표가 된다.
2. 재투표도 칸 1 김밥 +1, 칸 2 라면 +1.
   - [ ] "결정: 김밥" 또는 "결정: 라면"이고, "재투표에서도 정해지지 않아서, 동점이었던 메뉴 중에서 무작위로 정했어요."가 보인다.
3. 새 방에서 1까지 똑같이 한 뒤, 재투표에서 둘 다 "다 좋음".
   - [ ] 같은 문구로 무작위로 정해지고, "재투표 결과" 자리에 "재투표에서는 아무도 표를 내지 않았어요."가 보인다.

### 6. 랜덤 선택: 아무도 메뉴를 내지 않음 (칸 2개, 모두 30초)

빠른 방 만들기의 [모두 30초]로 방을 만든다.

1. 시작한 뒤 두 칸 모두 "다 좋음".
   - [ ] "랜덤 선택"이 되고 "아무도 메뉴를 제안하지 않아서, 랜덤으로 뽑힌 한 사람이 메뉴를 정해요. 누가 뽑혔는지는 비밀이에요."가 보인다. "몇 번째 뽑기"는 보이지 않는다.
   - [ ] 한 칸에만 "내가 뽑혔어요!"가 뜨고, 다른 칸에는 "누군가 뽑혀서 메뉴를 정하고 있어요. 시간 안에 정하지 않으면 다른 사람이 뽑혀요."가 보인다.
   - [ ] "다른 사람 뽑기"는 칸 1(방장)에만 있다.
2. 아무것도 하지 않고 30초 기다린다.
   - [ ] 다른 칸이 뽑히고, 남은 시간이 다시 30초부터 줄어든다. 칸 1(방장)에만 "지금 2번째 뽑기예요."가 보인다.
3. 30초 더 기다린다.
   - [ ] 더는 다시 뽑지 않고(칸 1은 "지금 2번째 뽑기예요." 그대로) 남은 시간이 사라진다.
   - [ ] 뽑힌 칸: "모두 한 번씩 뽑혀서 이제 시간 제한이 없어요. 진짜 내가 좋아하는 걸로 가자!"
   - [ ] 다른 칸: "모두 한 번씩 뽑혀서, 이제는 자동으로 다시 뽑지 않아요."
   - [ ] 칸 1(방장)의 안내: "다른 사람 뽑기를 누르면 처음부터 다시 뽑아요."
4. 칸 1에서 "다른 사람 뽑기"를 누른다.
   - [ ] 확인창 없이 바로 칸 1에 "지금 3번째 뽑기예요."가 보이고, 바로 앞에 뽑힌 칸이 아닌 칸이 뽑히며, 남은 시간이 다시 생긴다.
5. 뽑힌 칸에서 "마라탕"을 쓰고 "이 메뉴로 정하기"를 누른다.
   - [ ] 모든 칸에 "결정: 마라탕"과 "랜덤으로 뽑힌 사람이 정했어요. 누가 정했는지는 비밀이에요."가 보인다.

### 7. 랜덤 선택: 아무도 투표하지 않음, 시간 제한 없음 (칸 2개)

1. 칸 1 "김밥", 칸 2 "라면" → 둘 다 "합치기 끝냄" → 투표에서 둘 다 "다 좋음".
   - [ ] "아무도 투표하지 않아서, 랜덤으로 뽑힌 한 사람이 메뉴를 정해요."가 보인다.
   - [ ] 남은 시간 자리에 "시간 제한 없음"이 보인다.
   - [ ] 뽑힌 칸: "진짜 내가 좋아하는 걸로 가자!"가 보이고, "나온 메뉴에서 고르기"에 김밥과 라면이 "고르기" 버튼과 함께 있다.
   - [ ] 다른 칸: "누군가 뽑혀서 메뉴를 정하고 있어요."만 보이고, 시간 이야기는 없다.
2. 1분 넘게 기다린다.
   - [ ] 다시 뽑지 않는다(칸 1에 "지금 2번째 뽑기예요."가 생기지 않는다). 시간 제한이 없으면 자동으로 다시 뽑지 않기 때문이다.
3. 칸 1에서 "다른 사람 뽑기"를 누른다.
   - [ ] 확인창 없이 바로 칸 1에 "지금 2번째 뽑기예요."가 보이고 다른 칸이 뽑힌다. 여전히 시간 제한이 없다. 칸 2에는 몇 번째인지 보이지 않는다.
4. 뽑힌 칸에서 김밥 옆 "고르기"를 누른다.
   - [ ] 입력칸에 "김밥"이 들어가고, "고르기" 버튼이 눌린 모양(굵은 글씨와 테두리)이 된다.
   - [ ] 아직 정해지지 않는다. 다른 칸은 그대로 "누군가 뽑혀서 메뉴를 정하고 있어요."다.
5. 입력칸을 "김밥 곱빼기"로 고치고 "이 메뉴로 정하기"를 누른다.
   - [ ] 확인창 없이 바로 모든 칸에 "결정: 김밥 곱빼기"와 "랜덤으로 뽑힌 사람이 정했어요. …"가 보인다.

### 8. 방장의 "다음 단계로"와 시간 초과 (칸 3개, 모두 30초)

빠른 방 만들기의 [모두 30초]로 방을 만든다.

1. 시작한 뒤 칸 1 "김밥", 칸 2 "라면"만 제안하고, 칸 3은 아무것도 하지 않는다.
2. 칸 1에서 "다음 단계로"를 한 번 누른다.
   - [ ] 칸 3이 끝내지 않았어도 "합치기 중"으로 넘어간다.
3. 아무도 아무것도 하지 않고 30초 기다린다.
   - [ ] 시간이 다 되면 "투표 중"으로 넘어간다.
4. 칸 1만 김밥 +1을 제출하고 30초 기다린다.
   - [ ] 시간이 다 되면 "결정: 김밥"이 된다. 내지 않은 사람은 투표하지 않은 것으로 센다.

### 9. 늦게 들어오기, 나갔다 들어오기, 새로고침 (칸 4개)

1. 방을 만들고 칸 2만 "들어가기". "시작"을 누르고 칸 1이 "김밥"을 제안한다.
2. 칸 3 "들어가기".
   - [ ] 모든 칸이 "참여 인원 3명 · 지금 접속 중 3명"으로 바뀌고, 칸 3도 바로 제안할 수 있다.
3. 칸 2 "라면", 칸 3 "떡볶이"를 제안한다(합치기 단계가 된다).
4. 칸 2 "새로고침".
   - [ ] 같은 참여자로 돌아온다. "참여 인원 3명 · 지금 접속 중 3명" 그대로이고, "라면"에 "(내 메뉴)"가 붙어 있다.
5. 칸 4 "들어가기".
   - [ ] "참여 인원 4명 · 지금 접속 중 4명"이 된다. 칸 4는 메뉴가 없어서 "메뉴를 내지 않아서 합칠 게 없어요."가 보인다.
6. 칸 2 "닫기". 그다음 칸 1, 3에서 "합치기 끝냄".
   - [ ] 10~20초쯤 뒤 다른 칸에 "참여 인원 4명 · 지금 접속 중 3명"이 보인다. 참여 인원은 줄지 않는다.
   - [ ] 칸 2가 끝내지 않고 나가서 바로 투표로 넘어가지 않는다("4명 중 3명 끝냄"). 나간 사람도 "모든 참여자"에 들어간다.
7. 칸 2 "들어가기".
   - [ ] 바로 "지금 접속 중 4명"으로 돌아온다.
   - [ ] 같은 참여자로 돌아와서 "합치기 끝냄"을 누를 수 있다. 누르면 바로 "투표 중"이 된다.
8. 모두 김밥 +1을 제출한다(늦게 들어온 칸 4도 투표할 수 있다).
   - [ ] "결정: 김밥"
9. 테스트 화면 위쪽의 방 주소를 "주소 복사"로 복사해서, 엣지나 크롬 시크릿 창에 붙여 넣어 연다.
   - [ ] 새 사람이라 "투표가 끝난 방이라 들어갈 수 없어요. 새 방을 만들어 주세요."가 보인다.
10. 칸 3 "닫기" 뒤 "들어가기".
    - [ ] 이미 참여한 사람이라 다시 들어와서 결과를 본다.

### 10. 서버가 다시 켜질 때 (칸 2개, 모두 30초)

연결이 끊겼다가 다시 연결되는지 본다. 개발자 도구의 "오프라인"으로는 이미 열린 SSE 연결이 끊기지 않아서, 서버를 껐다 켠다.

1. 빠른 방 만들기의 [모두 30초]로 방을 만들고, 모두 들어가서 시작한다.
2. 백엔드를 끈다(실행한 터미널에서 Ctrl+C. Claude가 띄워 둔 서버면 Claude에게 껐다 켜 달라고 한다).
   - [ ] 30초 안에 모든 칸에 "연결이 끊겨서 다시 연결하는 중이에요..."가 보인다. 화면은 서버가 10초마다 보내는 신호를 25초 넘게 못 받으면 끊긴 것으로 알아챈다.
3. 30초 넘게 기다렸다가 백엔드를 다시 켠다(`./gradlew bootRun`).
   - [ ] 새로고침하지 않아도 끊김 안내가 사라지고, 시간이 다 된 제안 단계가 다음 단계로 넘어가 있다.

### 11. 이상한 입력과 버튼 연타 (칸 2개)

1. 제안 단계에서 확인한다.
   - [ ] 공백만 쓰고 "제안하기"를 누르면 아무 일도 일어나지 않는다.
   - [ ] 30자를 넘게 쓰려고 하면 30자에서 더 써지지 않는다.
   - [ ] "  김밥  "처럼 앞뒤에 공백을 넣으면 목록에 "김밥"으로 보인다.
   - [ ] 이모지가 들어간 이름("🍜 라멘")도 그대로 보인다.
   - [ ] "제안하기"를 빠르게 여러 번 눌러도 내 메뉴는 하나다.
2. 두 칸 모두 메뉴를 내서 합치기 단계로 간다. 칸 2에서 칸 1 메뉴 옆 "이 메뉴에 합치기"를 빠르게 두 번 누른다.
   - [ ] 오류 안내("이미 …") 없이 요청이 한 번만 간다(합치기 현황에 요청이 하나).
3. 칸 1에서 합치기 질문에 "합치지 않기"를 누르고, 바로 "합치기 끝냄"을 누른다.
   - [ ] 둘 다 처리된다. 같은 버튼을 두 번 누르는 것만 막고, 다른 버튼은 막지 않는다.
4. 방장의 "다음 단계로"를 더블클릭한다.
   - [ ] 한 단계만 넘어간다.

### 12. 휴대폰 화면 (칸 4개, 크롬 개발자 도구)

1. 칸 4개로 시나리오 1을 하면서 본다.
   - [ ] 글자가 칸 밖으로 넘치거나 버튼이 잘리지 않는다(칸 너비가 휴대폰과 비슷하다).
2. 테스트 화면 탭을 닫고 http://localhost:5173 을 연 뒤, F12 → 휴대폰 모양 아이콘(기기 툴바)에서 작은 휴대폰(예: iPhone SE)을 고른다. 방을 만들고 투표 화면까지 간다.
   - [ ] 가로로 스크롤하지 않아도 모든 내용이 보인다.
   - [ ] 버튼이 손가락으로 누르기에 너무 작지 않다.

## 배포한 뒤 확인 (실제 휴대폰 2대 이상)

배포한 서버에서 짧게 확인한다(스모크 테스트).

- [ ] 방을 만들고 링크를 메신저로 보내서, 받은 휴대폰에서 링크를 바로 열면 방 화면이 나온다(404가 아니다).
- [ ] 새로고침해도 같은 참여자다(참여 인원이 늘지 않는다).
- [ ] 제안 → 투표 → 결정까지 두 휴대폰에서 실시간으로 같이 바뀐다.
- [ ] 한 휴대폰을 비행기 모드로 20초 두는 동안 다른 휴대폰에서 제안하고, 비행기 모드를 끄면 새로고침 없이 따라잡는다.
- [ ] "참여 링크 복사"가 된다. HTTPS가 아니면 복사 대신 링크가 담긴 창이 뜬다.

## 찾은 문제

1번은 체크리스트를 만들면서 Claude가 미리 해 보다가 찾았다.

| 번호 | 시나리오 | 무엇을 했나 | 무엇이 보였나 (기대와 다른 점) | 상태 |
|---|---|---|---|---|
| 1 | 10 | 개발 서버에서 백엔드를 껐다가 다시 켰다 | "연결이 끊겨서…" 안내도 없이 화면이 그대로 멈추고, 새로고침하기 전까지 아무 변화도 받지 못했다. Vite 프록시가 백엔드 쪽 연결이 끊긴 것을 브라우저에 전하지 않아서, 브라우저는 연결이 살아 있다고 믿는다. 백엔드에 바로 붙은 연결은 꺼진 동안 3초마다 다시 시도해서 저절로 돌아왔다. 휴대폰 네트워크가 바뀔 때처럼 연결이 소리 없이 끊기는 일은 배포한 뒤에도 생길 수 있어서, 화면이 연결 상태를 스스로 확인해야 한다 | 고침. 화면이 서버의 신호(ping)를 25초 넘게 못 받으면 다시 연결한다([기술 결정 56번](decisions.md#56-소리-없이-끊긴-연결을-화면이-알아채기-찾은-문제-1번)) |

## 디자인 의견

버그는 아니지만 바꾸고 싶은 점을 적는다. 기능이 다 된 뒤 디자인을 개선할 때 본다.

-
